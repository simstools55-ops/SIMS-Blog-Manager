# SIMS-Blog-Manager v5.13.3

v5.13.2でも旧モニタリングサイクルが残る実データケースが確認されたため、
表示後の重複除去ではなく、**改善履歴を読み込んだ直後に記事単位で最新サイクルへ集約**する方式へ変更しました。

## 修正内容

- 改善履歴をArticleID → URL → 記事タイトルの順で記事単位に識別
- 各記事の最新改善サイクルだけを「改善の推移」生成対象にする
- 新しい8/23サイクルがある記事では、7/16の旧「見直し候補」は行そのものを生成しない
- 最新サイクルが4回/4回かつ
  - 大きく改善
  - 改善
  - 改善傾向
  の場合は現役一覧から卒業
- 最新サイクルが
  - 見直し候補
  - 要確認
  - 変化小
  - 経過観察
  等で未解決なら表示継続
- 改善履歴とTreatment_Performanceの過去データは削除しない

## 今回の確認対象

1. 「Something went wrong...」
   - 7/16 見直し候補 → 非表示
   - 8/23 測定待ち → 表示

2. 「Windows 11 25H2 ダウンロード完全ガイド」
   - 7/16 見直し候補 → 非表示
   - 8/23 測定待ち → 表示

3. 「YouTubeの自動再生をオフにする方法」
   - 7/22 4回/4回・改善 → 非表示

4. Wi-Fiルーター電気代
   - 4回/4回・見直し候補、まだ新サイクルなし → 表示継続
