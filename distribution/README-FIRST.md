# SIMS-Blog-Manager v5.13.2

v5.13.1で同一記事の旧モニタリング行が「改善の推移」に残るケースが確認されたため、
表示直前にも二重の安全判定を入れたPATCHです。

## 修正内容

- 「改善の推移」の表示行を最終段で正規化
- 同一記事の判定に以下を併用
  - ArticleID
  - 正規化URL
  - 正規化した記事タイトル
- 改善実施日を優先し、同日なら改善履歴IDで最新サイクルを判定
- 新しいモニターサイクルが始まった記事は、旧「見直し候補」行を非表示
- 4回/4回かつ「大きく改善 / 改善 / 改善傾向」の最新サイクルは現役一覧から卒業
- 「見直し候補 / 要確認 / 変化小」など、まだ次の処置が終わっていない最新サイクルは表示継続
- 旧サイクルは改善履歴・Treatment_Performanceから削除しない

## 今回確認する代表例

### 非表示になる旧行
- 2026/7/16
  「Something went wrong and the content wasn't generated.」
  4回/4回・見直し候補
- 2026/7/16
  「Windows 11 25H2 ダウンロード完全ガイド」
  4回/4回・見直し候補

### 表示を残す新行
- 2026/8/23 同2記事
  0回/4回・測定待ち

### 改善成功で卒業
- 4回/4回で「改善」「大きく改善」「改善傾向」の最新サイクル
