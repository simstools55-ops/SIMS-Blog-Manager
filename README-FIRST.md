# SIMS-Blog-Manager v5.13.4

## 根本原因

v5.13.1〜v5.13.3で「改善の推移」の重複除去を修正しても旧行が残った原因を、
実データとコードの両方から特定しました。

`改善履歴` を表示用に整える処理が、Doctor経路の履歴について、
**すでに正しい改善日が入っていても最新Doctor Caseの完了日で上書きする**
ことがありました。

その結果、本来

- 旧サイクル：2026/7/16
- 新サイクル：2026/8/23

であるものが、改善履歴では両方 2026/8/23 になり、
新旧判定が壊れていました。

## v5.13.4修正

- 改善日はモニタリングサイクル固有の**不変値**として扱う
- 有効な改善日はDoctor Case情報で上書きしない
- Doctor履歴の日付補完は「日付が壊れている場合」だけ行う
- 補完キーはArticleIDではなく**改善履歴ID**を優先
- 記事単位で最新Caseの日付を流用する処理を廃止
- すでに壊れた履歴は、現在の「改善の推移」に残っている
  `改善履歴ID ↔ 改善実施日` の対応から自動修復
- v5.13.3で誤エスケープされていた正規表現も修正
  - 空白正規化
  - 改善履歴IDの数値取得
